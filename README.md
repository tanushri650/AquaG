AquaG --- Urban Flood Nowcasting & Response System
SIH Problem Statement: SIH26085
Geographic focus: Delhi, India
Project type: Geospatial flood-risk and response-planning prototype
AquaG combines rainfall, terrain, drainage-network information,
historical flood features, population exposure, critical infrastructure,
and road connectivity to support short-horizon urban flood-risk
assessment. Its GIS dashboard visualizes flood exposure and response
priorities, while AquaGraph supports risk-aware route planning.
Model transparency: The current prototype uses an XGBoost
flood-severity classifier and a deterministic hydro-spatial
water-depth proxy. The displayed street-level water depth is an
estimate, not calibrated sensor-measured ground truth. The prototype
does not currently claim a complete calibrated Delhi-wide hydraulic
simulation or a live Doppler Weather Radar/SCADA feed.

Features
- Short-horizon scenarios: T+0, +30 minutes, +1 hour, +2 hours, and +3
  hours.
- XGBoost classification of flood severity (Low / Medium / High,
  according to model configuration).
- Hydro-spatial proxy estimates for indicative street-level
  waterlogging.
- GIS layers for drainage, waterlogging, flood risk, critical
  infrastructure, population priority, and routes.
- Population and critical-asset prioritization to support response
  planning.
- AquaGraph road-network routing with flood-risk-aware logic.
- Pump-station registry metadata, without inventing missing
  coordinates or telemetry.
- Bright and Dark dashboard themes.

The current depth layer is generated by deterministic hydro-spatial
logic. A future hydraulic upgrade could use EPA SWMM, subject to
verified drainage geometry and engineering parameters.
Why XGBoost?
XGBoost is suitable for structured/tabular features and can learn
nonlinear relationships among rainfall, terrain, drainage proximity, and
flood history. Once trained, it also supports fast inference for
dashboard updates.

  Current flood-severity  XGBoost classifier      Category such as Low /
  prediction                                      Medium / High
  Possible future depth   XGBoost regressor, if   Continuous value,
  prediction              trained on measured     e.g. centimetres
                          depth labels            
  Current prototype depth Deterministic           Indicative depth in
  estimate                hydro-spatial proxy     centimetres
The current water-depth estimate is not an XGBoost regression
output. A depth regressor should only be claimed after training and
validating it on suitable observed-depth labels.

Historical flood information
Past flood history is represented by the flood_history_count feature
in zone_flood_data_1000plus.csv. This does not mean the project
has a complete independent street-level ground-truth database containing
event timestamps, measured depths, durations, and mapped extents.
Technology stack
- Frontend: HTML, CSS, JavaScript
- Mapping: Leaflet and OpenStreetMap-based layers
- Backend: Python, FastAPI, Uvicorn
- Machine learning: XGBoost, scikit-learn, joblib
- Geospatial/data processing: GeoPandas, Rasterio, Shapely,
  PyProj, NumPy, pandas
- Routing: AquaGraph road graph and A*-style risk-aware route
  logic

Run locally
1. Start the backend
Open a terminal in the backend directory:
python -m pip install -r requirements.txt
python -m uvicorn main:app --reload --port 8001
Health endpoint:
http://127.0.0.1:8001/health
Interactive API documentation:
http://127.0.0.1:8001/docs
2. Start the frontend
Serve the repository root using VS Code Live Server or another static
server, then open index.html.
The frontend API base URL must match the backend. Local development has
used:
http://127.0.0.1:8001
If the dashboard cannot connect, check that the backend is running,
verify the API base URL, inspect browser DevTools Console/Network, and
confirm CORS settings.
API endpoints
Endpoints exposed during development have included /health,
/predict, /waterlogging, /infrastructure, /population-priority,
and /pumps. Schemas may change; use /docs from the running backend
for the current contract.
Limitations and responsible interpretation
- Water-depth values are proxy estimates, not verified sensor
  measurements.
- The flood_history_count feature is not proof of validation against
  an independent street-level flood-event dataset.
- Full hydraulic coupling needs verified pipe/link geometry,
  elevations/invert levels, cross-sections/diameters, roughness, pump
  curves, boundary conditions, and calibration data.
- Verified coordinates and live SCADA telemetry are not available for
  every pump station.
- A live Doppler Weather Radar nowcast feed is not currently
  connected.
- Routing is decision support; follow official emergency guidance and
  road-closure information.
Roadmap
1. Verify the exact model features, labels, train/test split, and
   evaluation metrics.
2. Obtain independent historical flood observations for validation.
3. Build a small verified catchment model with EPA SWMM or another
   suitable hydraulic engine.
4. Clearly separate verified engineering values from assumptions.
5. Couple rainfall-runoff, drainage capacity/surcharge/backflow, and
   surface inundation.
6. Integrate a licensed live radar/nowcast feed when available.
7. Validate routes against observed road closures and operational
   constraints.

Project status
AquaG is a geospatial flood-risk and response-planning prototype for
Delhi. It combines ML-based flood-severity classification, hydro-spatial
exposure estimates, GIS overlays, population/asset prioritization, and
risk-aware routing. Independent ground-truth validation and hydraulic
coupling are planned next.
